# Состояние проекта — Говорилка

Обновлено: 28.08.2026

## Что это

Портативное приложение для Windows: держишь горячую клавишу, говоришь,
отпускаешь — текст сам появляется в том поле, где стоял курсор. Распознаёт
Gemini 3.5 Transcribe. Пользователь — Balance, для диктовки задач и переписки.

## Где мы сейчас

Код написан и **прошёл полное независимое ревью 28.08.2026**. 227
автоматических тестов проходят. Собирается в один `.exe` через `build.bat`
(PyInstaller) и в облаке GitHub при каждом изменении кода.

Что есть:

- трей, окно настроек, глобальный хоткей с удержанием (по умолчанию Ctrl+Alt+Space);
- запись микрофона в память, отправка в Gemini, автоматическая вставка текста;
- двухслойный словарь: подсказка терминов модели плюс локальные правила замен
  («клоткот» → `Claude Code`);
- настройки в `%APPDATA%\VoiceDictation\`, ключ API в `.exe` не попадает;
- аудио удаляется с серверов Google сразу после расшифровки.

## Готовый файл

Свежий `.exe` всегда здесь:
https://github.com/Balance134/Govorilka/releases/tag/latest
(размер ~53 МБ, установка не нужна). Настройка сборки —
`.github/workflows/build-windows.yml`. Релиз больше не удаляется на каждой
сборке — файл просто заменяется, ссылка живая всегда.

## Ревью 28.08.2026 — что было починено

Пять блокеров, два из которых означали, что программа не заработала бы:

1. **Вставка текста не работала бы вообще** — буфер обмена открывался без
   окна-владельца, Windows в этом случае обязана отклонить запись.
2. **«Выход» падал после первой удачной диктовки** — обращение к уже
   уничтоженному рабочему потоку.
3. **Правила замен шли каскадом** — результат одной замены подхватывался
   другой; пара взаимных правил схлопывалась в ничто. Не видно, пока правила
   не пересекаются, но начало бы молча портить текст при дополнении таблицы.
4. **Мьютекс единственного экземпляра** создавался в пространстве, недоступном
   пользователю без прав администратора.
5. **Пропущенное отпускание клавиши** (выскочил запрос прав Windows) — микрофон
   писал бы бесконечно, горячая клавиша умирала до перезапуска.

Плюс около полусотни находок помельче: не ждали готовности загруженного файла,
нет повторов при обрыве сети, мёртвая ветка обнаружения выдернутого микрофона,
метка BOM в файле настроек стирала ключ API, строки в спецификации сборки,
которые якобы кладут звуковую библиотеку в `.exe`, на самом деле ничего не
делали (работало случайно, за счёт чужой заготовки).

Ход ревью — `РЕВЬЮ-ХОД.md`, промт — `РЕВЬЮ-ПРОМТ.md`.

## Что дальше — ручные проверки на живой Windows

Всё, что чинилось по документации Microsoft, а не по запуску, на сервере
проверить нельзя. Скачать `.exe` по ссылке выше и пройти список из
`voice-dictation/README.md`, раздел «Ручная проверка на Windows» — пункты
14–20 добавлены после ревью и проверяют ровно те места, где были блокеры.

Важнее всего два: **вставка текста** и **«Выход» после диктовки**.

## ⚠️ Открытый хвост — закрыть репозиторий обратно

**28.08.2026 репозиторий временно сделан ОТКРЫТЫМ** по прямой просьбе Balance,
чтобы он смог скачать `.exe` без входа в GitHub. Договорённость: как только
скачает — закрыть обратно.

Закрыть командой:
```
gh api -X PATCH repos/Balance134/Govorilka -f visibility=private
```

Перед открытием проверено: ключей и секретов ни в коде, ни во всей истории
коммитов нет, файлов вроде `.env` в репозитории нет.

Временные файлы раздачи лежат в `/root/govorilka-download/` на сервере 95
(сам `.exe` плюс две части и `СКЛЕИТЬ.bat`) — удалить вместе с закрытием.

### Почему пришлось открывать

Прямая ссылка с сервера 95 не работает: **Hetzner режет все порты, кроме 80 и
443**, до сервера запрос просто не доходит. Порты 80/443 заняты общим Caddy,
через который идут живые сайты клиентов — ради одного файла туда не лезли.
Передать файл вложением в чат тоже нельзя: 51 МБ против лимита 30 МБ, а сжатие
не помогает, внутри `.exe` всё уже упаковано.

## Открытые вопросы

- Нужен ли автозапуск вместе с Windows — пока не делали.
- Паспорта безопасности у проекта нет. Приложение локальное, чужих данных и
  денег не трогает; ключ Gemini лежит в открытом виде в `config.json` — это
  единственное место, где стоит принять решение осознанно.
- Комбинации вроде `Ctrl+Alt+Shift+Delete` и `Win+Shift+L` парсер пропускает
  как допустимые горячие клавиши. На практике Windows их всё равно перехватит,
  но список запрещённых комбинаций стоит однажды дописать.
